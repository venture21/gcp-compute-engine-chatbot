STEP 01

IDE와 gcloud 확인

Antigravity IDE에서 이 저장소 폴더를 열고 Terminal 패널을 선택합니다. 이 실습은 프로젝트 탐색기와 통합 터미널이 있는 IDE 창에서 진행했습니다. 터미널 패널을 최대화하면 출력 결과를 읽기 쉽습니다.

현재 폴더, gcloud 버전, 활성 로그인 계정, 기본 프로젝트를 차례로 확인합니다. 이 환경에서는 Google Cloud SDK 575.0.0과 프로젝트 sesac-dev-400904를 확인했습니다.

새 환경에서 활성 계정이 없다면 gcloud auth login을 실행하고 본인 계정으로 로그인합니다. 이후 명령에는 --project를 명시해 배포 대상을 고정합니다.

pwd
gcloud --version
gcloud auth list --filter=status:ACTIVE --format='table(account,status)'
gcloud config get-value project
STEP 02

클라우드 사전 조건 확인

us-central1에서 기존 Cloud Run 서비스는 0개였습니다. Cloud Run, Cloud Build, Artifact Registry, Secret Manager, IAM API는 모두 활성화되어 있었고, GEMINI_API_KEY 버전 1의 상태는 enabled였습니다.

이 단계의 시크릿 조회는 이름과 활성 상태만 표시합니다. 실제 API 키 값은 읽거나 화면에 출력하지 않습니다.

gcloud run services list --project=sesac-dev-400904 --region=us-central1
gcloud services list --enabled --project=sesac-dev-400904 --filter='config.name:(run.googleapis.com cloudbuild.googleapis.com artifactregistry.googleapis.com secretmanager.googleapis.com iam.googleapis.com)' --format='table(config.name)'
gcloud iam service-accounts list --project=sesac-dev-400904 --format='table(email,disabled)'
gcloud secrets versions list GEMINI_API_KEY --project=sesac-dev-400904 --format='table(name,state)'
STEP 03

업로드 소스 확인

괄호 안에서 cloud_run으로 이동하여 Cloud Build에 전송될 파일을 확인합니다. 괄호가 끝나면 원래 프로젝트 폴더에서 계속 작업합니다.

목록은 server.py, requirements.txt, Dockerfile, 두 ignore 파일, public의 HTML·CSS·JS입니다. .gcloudignore가 업로드 범위를 제한합니다. 로컬 .env, Compute Engine 코드, 문서와 캡처 이미지는 업로드 목록에 포함되지 않았습니다.

(cd cloud_run && gcloud meta list-files-for-upload)
STEP 04

배포 명령 미리보기

--dry-run은 실제 리소스를 변경하지 않고 배포 스크립트가 실행할 gcloud 명령을 출력합니다. 이 단계에서 소스 경로, 서비스 이름, 시크릿 버전, 런타임 설정과 인증 방식을 검토했습니다.

실행 계정gemini-chatbot-run@sesac-dev-400904.iam.gserviceaccount.com
이 프로젝트의 GEMINI_API_KEY 시크릿에 한해 roles/secretmanager.secretAccessor를 부여할 예정입니다.
빌드 계정gemini-chatbot-build@sesac-dev-400904.iam.gserviceaccount.com
프로젝트에 roles/run.builder를 부여할 예정입니다. 소스를 컨테이너 이미지로 빌드하고 저장하는 데 사용합니다.

이 스크립트의 기본 배포는 --invoker-iam-check --no-allow-unauthenticated를 사용합니다. HTTPS 주소가 생기더라도 호출자는 IAM 인증이 필요합니다.

PROJECT_ID=sesac-dev-400904 \
REGION=us-central1 \
SERVICE_NAME=gemini-chatbot \
SECRET_VERSION=1 \
bash cloud_run/deploy/deploy.sh --dry-run
STEP 05

실제 배포 실행

아직 실행하지 않은 단계
새 IAM 권한 부여 확인 후 아래 명령을 실행합니다. 배포 결과 화면은 완료 후 이 위치에 추가합니다.

--dry-run을 제거하면 스크립트가 전용 계정과 권한을 준비하고 gcloud run deploy --source를 실행합니다. Cloud Build가 Dockerfile로 이미지를 만들고 Artifact Registry에 저장한 뒤, Cloud Run이 해당 이미지를 실행합니다. 환경에 따라 빌드에 몇 분이 걸릴 수 있습니다.

PROJECT_ID=sesac-dev-400904 \
REGION=us-central1 \
SERVICE_NAME=gemini-chatbot \
SECRET_VERSION=1 \
bash cloud_run/deploy/deploy.sh
STEP 06

배포 후 접속 확인

배포 완료 후 수행할 확인 절차입니다. 현재 이 단계의 실행 결과는 없습니다.

서비스 URL과 준비 상태를 조회합니다. 인증이 필요한 서비스를 개발 환경 브라우저에서 보려면, Cloud Run 호출 권한이 있는 gcloud 로그인 계정으로 로컬 프록시를 실행합니다.

프록시가 실행 중인 동안 브라우저에서 http://127.0.0.1:8080을 엽니다. 이 주소는 내 컴퓨터의 접속 통로이며, 실제 컨테이너는 Cloud Run에서 실행됩니다. 프록시를 종료하려면 해당 터미널에서 Ctrl+C를 누릅니다.

/healthz는 프로세스 상태, /api/status의 hasApiKey는 키 설정 여부를 확인합니다. 실제 Gemini 응답까지 검증하려면 채팅 요청을 별도로 보내야 합니다.

gcloud run services describe gemini-chatbot \
  --project=sesac-dev-400904 --region=us-central1 \
  --format='yaml(status.url,status.conditions,status.latestReadyRevisionName)'

gcloud run services proxy gemini-chatbot \
  --project=sesac-dev-400904 --region=us-central1 --port=8080
